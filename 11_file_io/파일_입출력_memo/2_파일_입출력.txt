1. FILE *fp = fopen("hello.txt", "r");
    => hello.txt라는 이름의 파일을 OS에게 열어 달라고 요청하는 코드입니다.
    => 실제 파일 데이터는 파일시스템을 통해 저장장치에 존재합니다.


2. OS가 파일을 열면 관리 정보가 생깁니다.
    => OS는 열린 파일에 대해 여러 정보를 관리해야 합니다.
    => 커널 내부에 열린 파일을 관리하기 위한 자료구조가 만들어지고 관리됩니다.
    => 현재 어디까지 읽었는가? / 어떤 프로세스가 열었는가? / 읽기 전용? | 쓰지 전용? / 파일 상태?


3. 커널의 관리 정보가 생긴 이후 파일 디스크립터가 반환됩니다.
    => 파일 디스크립터 : 프로세스가 열린 파일을 참조하기 위해 사용하는 번호입니다.
    => OS는 프로세스가 가지고 있는 파일 디스크립터가 무엇인지 알아야 합니다. -> 이 때 fd table을 사용합니다.
    => fd table : fd 번호와 그 번호가 의미하는 열린 파일을 연결해 놓은 표입니다.
    => fd table은 프로세스마다 fd table이 하나씩 있고, 그 fd table은 커널이 관리합니다.
    커널
    │
    ├── 프로세스 A의 fd table
    │     0 → stdin
    │     1 → stdout
    │     2 → stderr
    │     3 → hello.txt
    │
    └── 프로세스 B의 fd table
        0 → stdin
        1 → stdout
        2 → stderr
        3 → aaa.txt


4. open을 통해서 파일을 연다고 가정
    4-1. OS는 열린 파일에 대한 관리의 책임이 존재합니다.
    4-2. 커널 영역에 해당 열린 파일에 대한 정보 + fd table를 자료구조 만들어 관리합니다.
    4-3. 그리고 open은 fd를 반환합니다. -> 커널의 fd table key 같은 것입니다.
    4-4. 다음 요청에는 fd를 가지고 요청 -> 커널이 해당 프로세스 fd table과 전달된 fd를 확인하고 요청을 시작합니다.
